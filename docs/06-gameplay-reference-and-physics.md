## 二、彈道物理守則

- **一般砲彈共用同一個重力** `STANDARD_GRAVITY_MILLI`（`projectileRegistry.ts`）。彈種的差異只放在爆炸半徑、傷害與風阻；
  重量不同的砲彈在真實世界落地加速度一樣，所以不要為了「重」而調高重力。
- 只有**特殊彈**（例如電漿彈）才可以自訂 `gravityMilli`，並要在程式註解標明是特殊彈。
- 物理核心 `simulateShot` 是每步「位置 += 速度、速度 += 風 + 重力」，垂直方向為標準拋物線，風是定值水平加速度。
- **播放時鐘固定**：每個模擬步 `PLAYBACK_MS_PER_STEP`（18 ms），**不依射程縮放**。以前把飛行時間夾在 min / max 之間，
  近距離射擊被拉慢、遠距離被壓快，每發看起來的重力都不同，因此移除。極近距離只保留 `MIN_FLIGHT_MS` 避免砲彈瞬間消失。
- 常見射擊（力道 60% ~ 100%、仰角 45° ~ 75°）約滯空 1.5 ~ 3.3 秒，仍保有「投籃拋物線節奏」；爆炸後停留 `postImpactHoldMs`。
- 改動任何物理常數時，電腦 AI（`botBrain`）與瞄準預覽都讀同一份 registry，會自動一致；P2P 雙端也共用，不需另外同步。

### 風速變化規則（已實作，`windRules.ts`）

風要像天氣一樣緩慢漂移，不是每回合重骰，否則玩家無法依風修正、也不符合現實。

- **風期**：風速以「風期」為單位維持不變，一個風期 = `max(3, 場上玩家數)` 個回合（1v1 為 3 回合，6 人為 6 回合，約等於輪完一圈）。
- **只在風期交界變動**：新風速 = 舊風速 + 隨機增量，增量限制在 `±ceil(maxWind / 4)`（例如 maxWind 8 → ±2，14 → ±4），再夾回 `±maxWind`。
  風向翻轉必須經過小風，不會從強順風瞬間變強逆風。
- **開局無風**（`initialWind = 0`），之後慢慢起風。
- **確定性**：隨機增量只由「對局 seed、新回合編號」雜湊決定，不依賴玩家操作或 `Math.random`，P2P 兩端各自算都得到相同結果。
- 各地圖的 `maxWind` 仍是風速上限（冰原強風、山谷溫和）。調整風期長度或增量時，同步修改 `windRules.ts` 的常數與本節。

## 三、坦克與砲彈平衡守則

**原則：血量愈少輸出愈高**，讓「對轟」互有勝負；機動力另外補償低血量，而不是疊加在輸出上。

- 傷害公式（`computeExplosionDamage`）是線性衰減：`(r - d) * maxDamage / r`。對一個落點誤差範圍較大的射手，
  期望傷害約正比於 `maxDamage × r²`，所以**爆炸半徑對強度的影響是平方**，調整時要特別小心。
- 現行陣容（§三之八）的機種差異放在**砲彈與被動**上，`damageMultiplier` 全部為 1.0；「血少輸出高」改由各機種的招牌砲彈體現
  （鷹眼 80 HP 配 75 傷害的狙擊彈、鐵壁堡壘 110 HP + 裝甲 + 紮根配 26 傷害的迫擊彈）。
- 砲彈之間沒有嚴格優劣：每種都在控制力、威力、射擊樣式、狀態之間取捨（§三之一），完整數值見 §三之八。

## 三之一、砲彈設計的四個平衡維度（新增砲彈或射擊樣式時必讀）

設計新砲彈不能只調傷害。每一種砲彈 + 坦克的組合都要同時考慮下面四個維度，並維持「總強度預算」大致相等：

| 維度 | 意義 | 目前對應的數值 | 提高時的代價 |
|---|---|---|---|
| **控制力**（力道 / 角度的容錯） | 玩家要多精準才打得中：彈道是否平直、受風影響多大、射程長短、有沒有輔助瞄準 | `gravityMilli`、`windMultiplier`、`speedMultiplier`、`magnetRadius`（吸附）、坦克 `windSensitivity`（見 §三之五） | 控制力高（平直、不怕風、有輔助）→ 單發威力要低 |
| **血量** | 承受對轟的時間 | `TankBlueprint.maxHp` | 血量高 → 輸出倍率低（血少輸出高） |
| **威力** | 分兩塊：**對坦克破壞力**（單發期望傷害 `maxDamage × damageRadius²`）與**地形破壞力**（挖坑範圍與深度），見 §三之二 | `damageRadius`（+ 坦克 `damageRadiusBonus`）、`terrainRadius`（+ `terrainRadiusBonus`）、`terrainDepth`（鑽地）、`terrainOp: 'fill'`（堆土）、`knockbackPx`（擊退）；另有 `maxDamage`、`damageMultiplier` | 威力高 → 控制力要差、或血量要少 |
| **特效（狀態）** | 命中後附加的持續效果：中毒、冰凍、破甲；射手自身的偵察；機種被動的紮根，見 §三之二 | `onHit` / `selfEffect` / `idleStatus`（`statuses/*.ts`） | 特效的價值要從直接傷害扣回來 |
| **射擊樣式** | 一次出手怎麼發射：單發、散彈、跳彈、碎裂、高拋穿地等 | `pattern`（`spreadPattern`）、`flight`（`bounce` / `shards` / `lob`，`shellFlight.ts`）、`fuse`（定時彈，§三之九）、`damageCapPerTank` | 樣式降低瞄準門檻或擴大覆蓋面 → 總傷害要折減 |

### 預算規則

- **總預算**：`HP × 威力 × 控制力折減 × 樣式折減 ≈ 常數`。任何一項加強，就要在另一項扣回來；沒有「全方面更好」的砲彈或坦克。
- **對人類愈好操作、對電腦精準操作愈不利**（設計原則）：容錯愈高、愈好上手的坦克或砲彈（風不敏感、彈道平直、吸附導引、散射範圍大），在電腦 100% 精準（σ → 0）的情況下應該愈不容易打贏。原因是玩家的操作能力與電腦能力不同：電腦的落點誤差可以近乎為零，若容錯來自「讓人好打」，電腦就會把這份優勢吃滿。因此設計時要同時看三種情況：
  ① 人類典型精度（σ = 25 ~ 70 px）下勝率在 40%~60%；
  ② 電腦精準（σ → 0）下，「好操作」的一方不應明顯更強（理想是勝率仍在約 40%~60%，至少不能系統性偏向高容錯的一方）；
  ③ 若有明顯的「好操作但電腦精準時偏弱」的組合，屬於可接受的設計取向，但要在文件中寫明，讓玩家知道這是取捨。
  對應到模擬器：`tools/balance/duel_sim.mjs` 已加入 σ = 5 px 的近似精準案例（標示為參考用，不納入 40%~60% 目標），用來檢查第②點。現行陣容 σ=5 為 0% / 100% 的命中次數對決：鷹眼最強、毒蠍最弱（毒霧彈範圍大、靠持續傷害，正是「好操作」的一方）。**沿用既有決定，接受為設計取捨（不調整數值）**：
  - 對應電腦「變態」等級（抖動為 0、會再細化瞄準）：容易操作的機種對上它幾乎必輸，符合「好操作的一方在精準時偏弱」的原則。
  - 此結果由命中次數決定（例如鷹眼狙擊彈 2 發即可打死毒蠍），調整會牽動 σ = 25~70 的範圍，代價過高。
  - **自適應電腦選角（設計方向）**：電腦會隨玩家進步而改選其他坦克。玩家實力提升後，電腦會捨棄容易操作的機種，因此「變態」等級的這種劣勢不需要事先提示，也不需要在選角或說明中標註難度。實作細節（判定玩家實力的依據、切換時機）待定，見 `todo.md`。
  - 模擬器的 σ=5 仍只作參考，不納入 40%~60% 目標；σ = 25 / 45 / 70 的目標不變。
- **控制力是「容易打中」的價值**：同樣的威力，風不敏感、彈道平直、射程長、能自動修正，就等於更容易命中，必須折價。
  特殊彈可以偏離標準重力（見第二節），但偏離多少就要用威力或血量補回來。
- **射擊樣式的折減基準**：
  - **霰彈 / 多顆散射**：n 顆彈丸各自造成小傷害，總單發期望傷害要略低於同級單發（覆蓋面大、命中穩定是它的價值）；
    近距離全中時的爆發傷害要設上限，避免貼臉秒殺低血量坦克。
  - **自動瞄準 / 追蹤**：降低的是「瞄準技巧」，所以單發威力要明顯低於同級手動彈，並限制只能鎖定一定範圍或每 N 回合一次；
    不得讓它完全取代手動瞄準，否則力道控制這個核心玩法會消失。
  - **連發 / 分裂**：每顆都要走同一套確定性彈道，傷害與半徑要按顆數攤薄。
- **力道控制力也要防止極端**：力道 / 角度的微調粒度、蓄力速度（`useBattleInput` 的 `CHARGE_RATE_PER_SEC`，所有坦克一致）屬於全域控制力設定，
  不隨砲彈改動；砲彈只透過速度、風阻、重力、散射範圍來改變容錯。
- **P2P 確定性**：新的射擊樣式（含散射的隨機偏移）必須只用 `FireActionCommand` 內的資料與共用種子計算，
  不可使用 `Math.random`，否則雙端彈道會不同步。

### 驗證流程

1. 新砲彈或新樣式先在 `tools/balance/duel_sim.mjs` 補上模型（例如霰彈 = 多顆彈丸各自抽落點、自動瞄準 = 降低 σ），
   再用三種瞄準精度（σ = 25 / 45 / 70 px）確認各配對勝率在約 40% ~ 60%。
2. 特別檢查：新砲彈是否在「所有 σ」下都被選為最佳砲彈（若是，代表它嚴格優於其他砲彈，需要加代價）。
3. 檢查極端情況：低血量坦克被近距離霰彈一發帶走的機率、自動瞄準是否讓 σ 小到無視地形。
4. 數值與模擬器手動同步後，才可以調整 `tankRegistry.ts` / `projectileRegistry.ts`。

### 格點精度與控制力（設計評估；角度粒度已決定，力道精度待定）

**現況（已量測）**
- 人類：角度 ▲▼ 每次 ±1°（另有 ±5°）；力道在充能時以 `Math.round` 取整數（`BattleHud.vue`）。
- 電腦「變態」：粗搜仰角每 4°、力道每 2 一格，再於最佳解附近以 ±4° / ±3 力道、每 1°/1 力道細化（`botBrain.ts`）。最終精度為 1°×1 力道。
- 相鄰格點的落點變化（平原、風速 0，射手固定）：+1 力道約 13~19 px，+1° 約 5~27 px（依角度而異）。這和傷害範圍 40 px 同一量級。

**量測結果**
- 在 500~1500 px 的 21 個目標位置上，電腦的整數格點**全部**找得到直擊（最小落點誤差 0 px）；直擊格點約佔 2.8%（每個目標約 388 發）。
- 因此對「變態」電腦，格點解析度**不會**造成落點失準，它的單發傷害固定為全額。電腦精度提高到小數點後兩位，對它的傷害分佈沒有實質影響（只是讓細化更精確）。
- 有地形遮擋、有風（電腦以 `simulateShot` 補償風）的情況尚未量測。

**評估結論**
- 人類的輸入粒度才是 σ≈0 時傷害變動的主要來源：步長 5~27 px 足以讓一發從直擊變成中等傷害。
- 提高人類精度（例如力道與角度保留到 0.01、以 xx.xx 顯示）等同提高**控制力**。依 §三之一的預算原則，這會改變人類對上各機種的勝率，且 σ 應依新精度重新對應，不能直接沿用現有 σ = 25 / 45 / 70。
- 力道的微調粒度被 §三之一的「驗證流程」視為全域控制力設定；改動屬於設計變更，需要先決定。

**已決定**
- **角度最小單位維持 1°**（人類與電腦皆然）。角度不做小數，▲▼ 與 ±5 的步長不變。
- **力道改用小數，精度為兩位小數（0.01），顯示為 xx.xx**（取代現行的整數取整）。已實作：`quantizePower`（`battleState.ts`）統一處理 HUD 的點擊、充能與開火，以及瞄準動畫。
- **電腦「變態」同步做力道的局部細化**：它是最精準的對手，力道也用小數細化。已實作（`botBrain.ts`）：最佳解附近角度 ±4°（每 1°）、力道 ±1（每 0.01）。因角度已是 1°、整數格點已能直擊，它的傷害不會因此改變，改變的只是它瞄準得更貼近。

**量測結果（力道 0.01 步長，平原、風速 0，11 個目標位置 500~1500 px）**
- 力道 +0.01 的落點變化為 0 px（四捨五入到整數 px 後看不出變化）。也就是說，力道的輸入精度已不是限制。
- 角度仍是 1° 一格。所有目標位置中，有 50~75 / 151 個整數角度能靠 0.01 力道打出直擊，總計 709 / 1661（約 43%）；整數力道時直擊格點只佔約 2.8%。
- 最佳落點誤差為 0 px，每個目標都有直擊解。

**結論**
- 力道改為兩位小數後，玩家能找到直擊的機會大幅提高（由約 3% 到約 43%）。這代表控制力明顯提高，需要用模擬器與實機重新檢查平衡。
- 人類的 σ 不再由輸入精度決定，而是由玩家的瞄準技術（手感、判斷）決定，現有 σ = 25 / 45 / 70 只是估計值，需要以實機遊玩資料校準。

**待決定**
- 無（小數位數與粒度已定案）。後續工作：以實機資料校準人類 σ，並在模擬器中重新跑各配對勝率。

## 三之二、威力拆分與狀態特效（已實作：威力拆分、中毒、冰凍、破甲、紮根、偵察、鑽地、堆土、擊退）

### 1. 威力是兩個獨立數值（已實作）

以前 `blastRadius` 同時決定「挖多大的坑」和「多遠內會受傷」，大範圍砲彈會同時是地形殺手與坦克殺手。
現在已拆開（`ProjectileBlueprint.damageRadius` / `terrainRadius`，坦克加成 `damageRadiusBonus` / `terrainRadiusBonus`），
現行砲彈已用到不同定位（例如震波彈 `terrainRadius` 0 只傷人不挖地、築壘彈 `damageRadius` 0 只堆土）：

| 數值 | 作用 | 設計提醒 |
|---|---|---|
| `damageRadius` / `maxDamage` | 對坦克的傷害（線性衰減，見 §三） | 影響對轟勝率，要過 `duel_sim.mjs` |
| `terrainRadius` | `carveCircle` 的挖坑半徑 | 影響地形玩法：打穿薄層讓對手墜落、挖掉掩體、削平高地 |
| `terrainDepth`（已實作） | 打在地面上時爆心往下移這麼多 px，挖坑與傷害都以鑽到的位置計算（直接命中坦克則在原地爆；`BEDROCK` 一律挖不動） | 鑽地彈可以穿過第一層再爆炸，但對坦克傷害要低 |
| `terrainOp: 'fill'`（已實作） | 在落點以 `terrainRadius` 堆出土丘（核心 `fillCircle`，只把空氣填成土壤）；土丘蓋到坦克時把坦克抬到新地表上，**不活埋**（避免硬控） | 連線重新同步的地形紀錄以負半徑表示堆土 |
| `knockbackPx`（已實作） | 爆炸範圍內的坦克沿地形（`walkAlongTerrain`）往遠離爆心的方向推，距離 = `knockbackPx × (r − d) / r`；被推出懸崖照一般下墜規則結算 | 在深淵地圖上等於附帶擊殺，`maxDamage` 要低 |

- **地形破壞力也要計價**：能一發打穿薄層的砲彈，在吊橋、浮空島這類地圖上等於「附帶墜落傷害」，
  因此它的 `maxDamage` 要比同級砲彈低。
- 反過來，**純傷害彈**（`terrainRadius` 小、`damageRadius` 大）打不穿地形，對躲在坑裡的對手有效，但不能改變地圖。
- 摔落傷害（`fallDamageFor`）與墜入深淵陣亡是地形破壞的副產品，評估砲彈強度時要把「能不能製造墜落」算進去。

### 2. 狀態特效（Status Effect）

狀態以回合為單位，掛在**坦克實體**上，只用整數與確定性規則結算（P2P 雙端一致，不可用 `Math.random`）。
已實作：`statusEffects.ts` + `statuses/<id>.ts`（一檔一狀態，自動收集），`TankEntity.statuses` 納入 `battleStateHash` 與快照。

- **回合計法**：`turnsLeft` = 還會影響幾個「自己的回合」。自己回合開始時結算持續傷害、套用燃料上限並減一；自己回合結束時移除到期的狀態（需要時改掛免疫）。
  因此被動效果（破甲、紮根、偵察）會一直持續到最後那個自己回合結束。
- **持續傷害可致死**：回合開始時被毒死的坦克直接跳過，換下一位；因此分出勝負時維持 `GAME_OVER`。畫面以狀態顏色跳出傷害數字，HUD 與坦克頭上顯示圖示與剩餘回合。
- 現有狀態：中毒（每回合固定傷害，`damageType: 'poison'`）、冰凍（燃料上限 × (1 − power%)，結束後 1 回合免疫）、破甲（裝甲與護盾失效）、
  夾住（裝甲與護盾失效 + 燃料上限 × (1 − power%)，結束後 1 回合免疫；寄居蟹鉗擊彈，即破甲 + 冰凍的組合，不跳過回合），紮根（下一次爆炸傷害 −power%，受傷一次就消失；由機種 `idleStatus` 在整回合沒移動時掛上）、偵察（瞄準預覽畫完整彈道與落點）。
  濕透（下一次受到的爆炸傷害 +power%，受傷一次就消失，結束後 1 回合免疫；海馬潮湧泡泡，見 §三之十一）。

| 狀態 | 效果 | 持續 | 結算時機 |
|---|---|---|---|
| 中毒 | 每回合固定扣血（`dotDamage`），不致死到 1 HP 以下可選 | 2 ~ 3 回合 | 該坦克自己回合開始時 |
| 冰凍 / 減速 | `moveFuel` 上限降低（例如 -50%），重度時只能原地射擊；**不跳過回合** | 1 ~ 2 回合 | 該坦克回合開始時套用燃料上限 |
| 燃燒（建議） | 持續傷害但數值較中毒高、持續較短；移動時會多掉血 | 1 ~ 2 回合 | 同中毒 |
| 護盾（狀態版，建議） | 吸收下一次傷害的一部分；對自己或隊友。（坦克本體的靜態護盾池已實作，見 §三之五） | 1 次 / 2 回合 | 受傷時 |
| 修復 / 淨化（建議） | 回血或清除負面狀態 | 立即 | 命中隊友或自己時 |
| 擊退（建議） | 把坦克沿爆炸反方向推開一小段（走 `walkAlongTerrain`），可能推下深淵 | 立即 | 爆炸結算時；`knockbackPx` 為負值時反向：把坦克拉向射手（舌鞭彈，見 §三之十二） |
| 風暴（建議） | 改變下一回合風向 / 風速 | 1 回合 | 回合推進時 |

**狀態規則（避免失控）**

- **不得硬控**：冰凍只削弱移動，不跳過整個回合，避免連續被控到無法遊玩。
- **不疊加同種狀態**：重複命中只刷新持續回合，不增加強度；可設定「結束後 1 回合免疫」避免被鎖死。
- **持續傷害不致命閾值**：預設 DOT 可以殺死坦克，但要在 HUD 清楚顯示剩餘回合與預估傷害，讓玩家能預測。
- **狀態是砲彈預算的一部分**：特效砲彈的 `maxDamage` 與 `damageRadius` 要比同級純傷害彈低，
  扣掉的量大約等於特效在該持續回合內的期望價值（中毒 ≈ `dotDamage × 回合數`）。
- **控制力搭配**：高威力 + 強特效的砲彈，控制力要差（受風大、射程短、初速慢）。
- **HUD 需求**：坦克頭像旁顯示狀態圖示與剩餘回合；砲彈清單顯示特效標籤。
- **資料驅動**：新增 `StatusEffectBlueprint` registry（比照坦克 / 砲彈 / 地圖 registry），
  `ProjectileBlueprint` 以 `onHit: { status, turns, power }` 引用，不在戰鬥邏輯內寫死特例。

### 3. 尚未做的砲彈構想（均需先通過 §三之一的驗證流程）

毒霧、凍結、鑽地、散彈、堆土已在 §三之八 的陣容中實作。仍是構想的：

| 建議 | 定位 | 威力分配 | 控制力 | 特效 |
|---|---|---|---|---|
| 追蹤彈 | 輔助瞄準 | 威力明顯低，限制次數 | 高（自動修正） | 無 |
| 修復彈 | 隊友支援 | 無傷害 | 一般 | 修復 / 淨化 |

- 每加一種，先更新 `duel_sim.mjs` 的模型再改數值。
- **版權提醒**：特效與砲彈的名稱、圖示與音效一律原創；可借用通用概念（中毒、冰凍），不使用其他遊戲的專有名稱或美術。

## 三之五、吸附、防護與風敏感度（已實作）

這一組機制補強「控制力」與「耐久」維度，全部資料驅動、整數確定性（P2P 兩端一致）。

### 1. 砲彈吸附與直擊加成
- `ProjectileBlueprint.magnetRadius`（px）與 `directHitMultiplier`；`prepareFireTrajectory` 中，砲彈進入**任何存活的非射手坦克**（含隊友，**友傷是刻意的技術風險**）吸附範圍且路徑無地形遮擋（`hasClearLine`），
  砲彈**不改變彈道**（肉眼不可見吸附，禁止做成導引彎折），沿原拋物線飛行，在範圍內取**最接近車心**的那一點引爆並判定命中；可命中範圍至少為 `HIT_CAPTURE_RADIUS_PX`（36 px），因此吸附半徑小於 36 的砲彈實際判定也是 36 px。`magnetRadius: 0` 為「純技術彈」。
- **設計原則：威力越大、導引越少**。吸附把「落點衰減」壓平成全額傷害，所以它等於控制力折價；高單發威力的砲彈吸附半徑要接近 0。
- 現況：吸附半徑 16~24 px（毒霧彈 24 最寬鬆、鑽地彈 16）；磁軌狙擊彈 `HAWK_RAIL`、築壘彈、偵察照明彈為 0（不導引）。數值見各 `projectiles/*.ts`。
- 多段彈道（跳彈、碎裂、高拋穿地）的每一段都會套用吸附，與開火結算、電腦瞄準、瞄準預覽共用 `shellFlight.ts` 的 `traceShell`。
  `directHitMultiplier` 目前皆為 1，保留作為日後調整旋鈕。
- **命中分級（2026-10-23 起取代「直擊吃滿」）**：可命中範圍是一個比車身大的圓（`HIT_CAPTURE_RADIUS_PX` 36 px），不是一個點。`commitFireImpact` 依爆心與車身中心（`tank.y - 10`）的距離給傷害比例（`hitGradeRatio`）：
  距離 ≤ `HIT_CORE_RADIUS_PX`（10 px，約車身面積 1/4~1/5）的**核心**吃滿 `maxDamage × directHitMultiplier`；核心往外線性遞減，到捕捉圈邊緣為 `HIT_EDGE_DAMAGE_RATIO`（40%）；實際傷害取「分級傷害」與「一般爆炸衰減」較大者。越靠中心傷害越高。`battle.test.ts` 有回歸測試。
  `duel_sim.mjs` 仍假設命中吃滿、不模擬此分級，真實平衡要靠實機確認並微調 36 / 40%。
- 2026-10-23 舊紀錄（已被上面的命中分級取代）：玩家反映完全命中太難，碰撞半徑 18 → 22 px、直擊判定 26 → 30 px（稍微放寬，所有砲彈一起受惠，含不吸附的純技術彈）。電腦瞄準本來就以 22 px 判定命中（`botBrain.ts`），兩者現在一致。`duel_sim.mjs` 不模擬這兩個半徑（本來就假設直擊吃滿），所以模擬勝率不受影響；實際效果要靠實機手感確認。
- 平衡：吸附會放大高單發砲彈的優勢；現行數值的模擬結果見 §三之八。

### 2. 坦克防護：裝甲 / 護盾 / 抗性
- `TankBlueprint.armor`（爆炸傷害固定減免，至少仍受 1 點）、`shield`（先於 HP 吸收、不回復，戰場上以青色細條顯示在血條上緣）、`resist: Partial<Record<DamageType, number>>`（0~1 減傷）。
- `DamageType` = `explosion | fall | poison | burn | movement`，後三者**預留**，尚無來源；日後的狀態特效（§三之二）結算時一律經 `mitigateDamage(spec, type, raw)`，並在各機種 `resist` 填入抗性。
- 墜入深淵與走出邊緣的陣亡無視護盾與抗性。
- 抗性 1.0 代表完全免疫（回傳 0，而不是至少 1 點）。狀態會改變結算：破甲時裝甲歸零、護盾不吸收；紮根時爆炸傷害再打折（`mitigateForTank`）。
- 現況：鐵壁堡壘 裝甲 1、摔落抗性 0.3、紮根；霜鯨 護盾 15；毒蠍 中毒抗性 1.0；地鼠工兵 摔落抗性 1.0；疾風遊俠 摔落抗性 0.5。

### 3. 各機種爬坡與摔落
- `climbPerPx`：可持續爬升的坡度，以每水平 1 px 可爬升的高度表示（鐵壁堡壘 / 霜鯨 2、毒蠍 / 鷹眼 3、疾風遊俠 / 地鼠工兵 4），傳入 `walkAlongTerrain`；`MAX_CLIMB_PER_PX` 只作為預設值。電腦走位規劃使用同一個值。
- **小土丘可跨越**（像履帶輾過小土堆）：不以單一像素的陡度判斷，短而陡的凸起（彈坑邊緣、碎石、小土丘）可以直接爬過去，只有大片連續陡坡與高牆擋得住。
  **尺度以車身為準**：車寬約 60 px、履帶約 24 px 高，比履帶矮的垂直斷面都不算牆。
  - **單步上限**：每水平 1 px 最多可上 `STEP_UP_PX`（24 px）。比這更高的垂直斷面就是牆。
  - **短距離總爬升**：最近 `STEP_WINDOW_PX`（20 px）水平距離內，總爬升不得超過 `climbPerPx × 20`（climbPerPx 2 → 40、3 → 60、4 → 80 px）。坡一直陡下去就會超過而停住，所以機種的爬坡差異仍然有效。
    視窗不能再加寬：加到 28 px 時，150 px 高土丘的陡峭基部也爬得上去，「大片陡坡擋住」就失效了。
  - **窄縫跨越**（`GAP_BRIDGE_PX` = 8）：寬度不到約 16 px 的裂縫（例如橋面被打穿的小洞）直接跨過去，車身維持原高度，不會卡在縫前、也不會整台掉進深淵；
    停在縫正上方時 `groundUnderTank` 以兩側地面為準，爆炸結算也不會掉下去。彈坑都比這寬，被炸出坑照樣會掉，跌落玩法不變。
  - 2026-10-23 調整前（單步 16 px、視窗 16 px）：在 8 張地圖各挖 12 個彈坑後讓坦克走完全程，30 px 以下的小障礙擋住 108 次；調整後 14 次，剩下的都是超過 24 px 的牆或低矮天花板。
  - 常數在 `battleState.ts`（`STEP_UP_PX`、`STEP_WINDOW_PX`、`GAP_BRIDGE_PX`）。調整時同步修改本節與 `src/test/battle.test.ts` 的「移動」測試（小凸起、22 px 台階、小土丘、窄縫可過；大片陡坡、高牆、寬溝擋住或掉落）。
- `fallSafePx`：被炸下墜後超過此高度才有摔落傷害（鐵壁堡壘 40 / 疾風遊俠 70 / 霜鯨 34 / 其餘 30），再套用 `resist.fall`。走下懸崖（落差超過全域 `FALL_SAFE_PX` 30 px）落在下層地面時，同樣依落差套用 `fallSafePx` 與 `resist.fall` 結算摔落傷害。

### 4. 風敏感度
- `TankBlueprint.windSensitivity`（鐵壁堡壘 / 霜鯨 0.9、疾風遊俠 1.1、鷹眼 0.7、其餘 1.0）。砲彈所受風力 = 全局風 × 砲彈 `windMultiplier` × 坦克風敏感度，統一經 `effectiveWindMilli()`（四捨五入為整數）。
- 結算（`prepareFireTrajectory`）、瞄準預覽（`BattleScene`）、電腦試算（`botBrain`）都必須使用同一函式，不可各自乘算。選車面板顯示的「受風影響」已含此係數。

### 5. 連線同步雜湊與自動重新同步
- `SYNC_HASH` 使用 `battleStateHash(state, terrainHash)`：地形雜湊 + 各坦克 x / y / hp / shield / 狀態 + 場上定時彈 x / y / 剩餘回合 / 傷害（FNV-1a），任何一端規則或數值不一致都能被偵測。
- 出手方在回合結算後送 `SYNC_HASH`；接收方**先暫存**，等本機也播完同一回合（`afterTurnSettled`）才比對，避免動畫未結束就誤報不一致。
- 不一致時以**房主為權威**自動修復：客端送 `RESYNC_REQUEST`（同一回合只送一次），房主回 `RESYNC_STATE`（整個 `BattleState` 的 JSON + 本局所有挖坑紀錄 `[x, y, r]`）；
  房主自己偵測到不一致則直接推送。客端依 seed 重建地形、重放挖坑、覆寫狀態並重畫。砲彈飛行中的收發都延後到回合結算後。
  地形只會被 `carveCircle` 改變，所以「挖坑紀錄」足以重建；若日後新增其他改地形的操作，必須一併記入此紀錄。

### 6. 砲管角度跟著車體、各機種仰角範圍（已實作，2026-10-23）
- **角度相對車體**：`tank.angle` 是相對車體的砲管角（HUD 顯示的仰角也是它）；實際發射方向（世界角度）= `angle - slopeDeg`（`worldAimAngle`，`slopeDeg` 順時針為正、即右側較低）。車體站在斜坡或被炸歪，砲管整個跟著轉：水平地面不變，右側較低時同樣的相對角打得更低。開火結算、瞄準預覽線、眼神方向與電腦 AI 都經此轉換；兩端用同一份 `slopeDeg` 狀態，不會失同步。
- **各機種仰角範圍**：`TankBlueprint.aimMinDeg / aimMaxDeg`（相對車體、左右對稱，0 = 水平、90 = 朝天）。範圍寬 = 控制力高，所以窄的機種要靠定位換取其他優勢（屬 §三之一「控制力」維度）。

  | 機種 | 仰角範圍 | 定位 |
  |---|---|---|
  | 鐵壁堡壘 | 35°~90° | 只能拋射、打不了平射；被貼臉時只能朝天打（刻意弱點） |
  | 疾風遊俠 | 5°~60° | 偏平射，近距離可平打，拋不過高牆 |
  | 鷹眼 | 8°~55° | 磁軌彈本來就平直，高角度沒意義 |
  | 毒蠍 | 12°~80° | 範圍寬，靠持續傷害補償 |
  | 霜鯨 | 15°~75° | 中庸 |
  | 地鼠工兵 | 20°~85° | 偏向往下挖，不需要太平的角度 |
- **執行處**：`clampAim`（`tankRegistry.ts`）在玩家輸入（`useBattleInput`、`handleUpdateAim`）、開火結算（`prepareFireTrajectory`，超出範圍一律夾回，防外掛與舊資料）與電腦搜尋 / 輸出都夾限；HUD 儀表盤把打不出去的角度段灰掉。
- **待驗證**：`duel_sim.mjs` 不模擬仰角限制（近身打不到、拋不過牆），數字要靠實機判斷；堡壘下限 35° 若讓疾風貼臉太強，可降到 25°。有 `battle.test.ts` 回歸測試（夾限、傾斜等價、電腦在範圍內出手）。

## 三之六、連線對戰中玩家斷線（已實作）

- 開房時由**房主**在房間規則選「玩家斷線時」：**認輸**（預設）或**電腦接手**；加入前在房間列表與等待室可見，開戰後鎖定。不採斷線後投票（會讓戰局停擺，兩人對戰也無意義）。
- 房主偵測到斷線，廣播 `PLAYER_LEFT { playerId, takeover }`，各端照辦（`forfeitPlayer` / `takeOverWithBot`）：
  - **認輸**：該坦克陣亡並退出出手順序；正輪到他就直接換下一位，整隊都離線則判對手獲勝。
  - **電腦接手**：坦克改為 CPU（中等難度）控制、血量與位置不變。電腦的決策只在**房主端**計算（`BattleArena` 的 `runsBot`），以一般的 `ACTION_MOVE` / `ACTION_FIRE` 廣播，其他端不跑 AI，確保確定性。
- 離線的玩家不會被帶入「再來一局」；房主自己離線則整場結束（房主是權威）。
- 房主驗證客端送來的動作：`playerId` 必須等於送件的連線槽位（`isForgedAction`），`ACTION_MOVE` 只接受當前出手玩家。
- 連線真人的彈藥配置見 §三之七；被接手的坦克改用預設明牌。

## 三之七、彈藥配置與迷霧（已實作；專屬彈藥待設計）

- **主彈 / 副彈**：每台坦克有一個砲彈池（`TankBlueprint.shots`，至少 `LOADOUT_SIZE` = 2 種），開戰前從池中選 2 種，依序為主彈、副彈。
  對戰中**只能在這兩種之間切換**（鍵盤 1 / 2）。選擇器 `LoadoutPicker`：點的砲彈已在另一格時兩格對調。
- **記住選擇**：以機種 id 為單位存在 `localStorage`（`tank:loadouts:v1`），下次選同一台自動帶出；沒有紀錄或已失效時取池中前兩種。單機熱座同機種共用同一份。
- **單機 / 電腦**：明牌，記在 `TankEntity.loadout`；電腦沒指定時帶預設前兩種。
- **連線對戰的迷霧**：開火前對手不知道你帶什麼（HUD 顯示「？ ？」），又要確保沒有中途偷換，所以用承諾 + 揭露（`domain/loadout.ts`）：
  - 每格各算一個葉子雜湊 `SHA-256(機種|格|砲彈|鹽)`，**鹽每格獨立**（共用鹽的話揭露一格就能反推另一格）。
  - 兩個葉子合成 Merkle 根，準備時只廣播這個根（`RosterSlot.loadoutRoot`），原文與鹽只留在本機（`LoadoutSecret`）。
  - 開火時 `ACTION_FIRE.reveal` 揭露「用的那一格」的鹽與「另一格的葉子雜湊」，收到的人重算根比對；沒用過的那一格整場都不會洩漏。
  - 驗證失敗（偽造、偷換、缺揭露）：`prepareFireTrajectory` 回傳 null，兩端一致拒絕開火。
  - 對戰中被電腦接手的坦克沒有真人的原文，改用預設明牌（`takeOverWithBot`，`PLAYER_LEFT` 兩端都會執行）。
  - 「再來一局」沿用同一個承諾，不需重新廣播。
- **待設計**：每台第三種（專屬）彈藥的數值與其他兩種的平衡（需先更新 `duel_sim.mjs`）；在那之前砲彈池剛好 2 種，選擇器只能對調主副順序。

### 4. 平衡模擬（`node tools/balance/duel_sim.mjs`，種子 20261022，每組 20000 場）

- 模型新增：散彈 / 碎裂（彈體共用瞄準誤差 + 固定偏移，散彈以 300 px 近距離換算）、中毒、破甲、護盾、紮根（假設堡壘整場不動）。

  - 鷹眼 vs 鐵壁堡壘 σ=25 約 67%：狙擊彈兩發打穿 110 HP（含裝甲與紮根），精準時是堡壘的剋星。
  - 疾風遊俠 vs 鷹眼 σ=45~70 約 66~68%：散彈容錯高、兩發上限 96 打死 80 HP 的鷹眼；瞄得不準時刺客壓制狙擊手。
  - 毒蠍 vs 鐵壁堡壘 σ=70 約 67%：中毒無視裝甲與紮根，設計上就是堡壘的剋星。
  - 霜鯨 vs 毒蠍 σ=25 約 68%：護盾 + 冰錐三片在精準時穩定命中。
- 2026-10-23 加大爆炸後重跑：σ = 45 / 70 所有配對落在 30% ~ 66%（比加大前的 32% ~ 68% 收斂）；σ = 25 霜鯨 vs 毒蠍升到約 74%（原 68%），仍屬上面「護盾 + 冰錐」的取捨。
- σ = 5（近似精準，參考用）仍是命中次數對決，見 §三之一的取捨說明。
- **2026-10-23 加入蝸牛迫擊**：`duel_sim.mjs` 新增定時彈模型（`FUSE_HIT_RATE = 0.55`，估計值，見 §三之九）。調整前蝸牛各配對勝率 90% 以上（血量、裝甲、傷害、範圍、風係數全部都比同級好，是「全方面更好」）；
  依「血少輸出高」下修後（HP 120 → 112、裝甲 2 → 1、螺旋迫擊彈風係數 3 → 5，傷害 / 範圍定為 31 / 48，黏殼彈範圍 72 → 66）：σ = 25 約 39% ~ 62%、σ = 45 約 40% ~ 50%、σ = 70 約 44% ~ 57%。
  σ = 25 對鐵壁堡壘 39%、對鷹眼 40%（精準時裝甲 + 紮根與狙擊彈仍占優）、對毒蠍 62% 屬可接受範圍。模擬器不含的價值：蝸牛的低初速（射程短）與全陣容最低機動，會讓實際勝率比模擬低一些。
- **2026-10-25 加入寄居蟹**：連發彈殼節數值經兩輪調整定案（20 ×3 / 32 / 26、單發上限 46），各配對勝率詳見 §三之十。

## 三之九、定時彈 `fuse`（已實作，2026-10-23，蝸牛迫擊 Snailer 的招牌機制）

現有陣容沒有「延遲引爆」，所以這是第 5 類砲彈行為（`shotExtensions.ts` 的第 5 項擴充點）：砲彈落地不爆炸，黏在落點留下一顆**定時彈**，倒數歸零才爆。
目的是讓對手「看得到威脅、必須花走位去躲」，玩法與直接傷害、持續傷害、控場都不同。

### 規則

- `ProjectileBlueprint.fuse = { turns }`。`turns: 2` = **放置當回合結束算第 1 次、對手的下一個回合結束算第 2 次** → 對手剛好有一個回合可以離開（多人對戰則是之後經過兩次回合結束）。
- 落地（或進入坦克 36 px 判定圈）時**不爆炸、不挖坑、不扣血、不給直擊傷害**，只在命中點登記一顆定時彈；爆炸用的 `maxDamage`（已含機種傷害倍率）、`damageRadius`、`terrainRadius` 在**放置當下定案**，之後引爆不再讀藍圖。
- 引爆走 `commitFireImpact(..., { detonating: true })`，與一般砲彈**同一套結算**（挖坑、裝甲 / 抗性、擊退、下墜與摔落、勝負判定）。引爆當作「地形爆炸」：沒有直擊加成。
- **不分敵我**：放置者自己站在範圍內一樣會被炸（刻意的技術風險，與吸附的友傷同一思路）；定時彈**不會跟著坦克移動**，也不會因為地形被挖掉而下墜（標記留在原地）。
- 同一時間場上可以有多顆；同時到期依放置順序逐顆引爆。放置者陣亡不影響已放置的定時彈。

### 資料與流程（兩端必須一致）

- `BattleState.charges?: Charge[]`（`id` = `${turnId}-${第幾顆}`、`x / y / owner / bulletType / turnsLeft / maxDamage / damageRadius / terrainRadius`）。舊快照沒有這個欄位，一律用 `chargesOf(state)` 讀取（缺值時補空陣列）。`battleStateHash` 納入每顆的 `x / y / turnsLeft / maxDamage`；`RESYNC_STATE` 整包 JSON 自然帶著。
- `detonateDueCharges(state, core)`（`useBattleTurn.ts`）：全部倒數 1 → 歸零的依序引爆並從清單移除 → 回傳 `bursts`（供畫面演出）與合併後的 `carves / damageByPlayer`。**必須在 `finalizeTurnAfterHold` 之前呼叫**。
- `BattleArena.vue` 的 `runChargeDetonations(done)` 把它接在兩個「回合結束」路徑上：**開火結算完（`onSequenceComplete`）** 與 **跳過回合（`applyPassCommand`）**；兩端在同一個時間點執行，所以結果一致。演出期間把 `phase` 切成 `FIRING` 擋住操作與電腦出手，演出完還原。
- 其他非常規的換回合路徑（走出邊緣陣亡、玩家斷線 `forfeitPlayer`）**不倒數**：定時彈會多留一個回合，屬已知且兩端一致的行為。
- 畫面（`BattleScene`）：`syncChargeVisuals` 依 `state.charges` 畫發光的殼、剩餘回合數（最後 1 回合加快閃爍）與爆炸範圍的淡色圈；`playChargeBursts` 負責「鏡頭移到爆心 → 爆炸（此刻才畫地形與傷害數字）→ 停留 → 換回合」。`ProjectileFlight.charge` 讓落地只濺一小團、不播爆炸。
- 電腦：`botBrain.planBotMove` 站在任何定時彈的爆炸範圍內（含自己放的）會先逃出範圍；rookie 等級不走位所以不會躲。選彈與瞄準仍把定時彈當一般傷害彈估算（不會刻意預判對手走位）。

### 平衡

- 定時彈的價值在「逼走位」而不是直接傷害：對手離開範圍就毫髮無傷，所以數值要比同級直擊彈高、範圍要大（蝸牛：36 傷害 / 範圍 66 / 挖坑 54，比螺旋迫擊彈的 31 / 48 / 48 高）。
- `duel_sim.mjs` 以 **`FUSE_HIT_RATE = 0.55`** 折減定時彈傷害（假設約 45% 的情況對手成功離開或被迫放棄原本站位）。**這是估計值、不是實測**；對電腦（會躲，但只躲範圍內）與人類（可能沒注意或走不開）的差異很大，實機遊玩後要回頭校正。移動力低的機種（鐵壁堡壘 140、蝸牛自己 100）較難躲開，這一點模擬器沒有分機種計算。
- 驗證：`src/test/mechanics.test.ts`「定時彈（fuse）」——落地不爆不挖不扣血、放置者回合結束倒數 1、對手回合結束引爆、離開範圍毫髮無傷與自傷、雜湊與舊快照相容、電腦逃離、兩端同指令雜湊一致。

## 三之三、電腦對手難度（已實作）

單機模式每一隊電腦可各自選難度（`RosterSlot.botLevel`，預設「中等」；未指定視為「強」）。電腦一律先暴力搜出最佳仰角 × 力道，再依難度加入誤差；數值集中在 `botBrain.ts` 的 `BOT_LEVEL_SPECS`。

| 等級 | 力道 / 仰角誤差（均勻分布） | 行為 | 實測落在傷害範圍內 |
|---|---|---|---|
| 新手 `rookie` | ±30 / ±16 | 偶爾才命中；不自行走位 | 約 9% |
| 弱 `weak` | ±14 / ±8 | 常打偏 | 約 19% |
| 中等 `normal` | ±6 / ±4 | 有偏差，約一半打得準 | 約 45% |
| 強 `hard` | ±3 / ±2 | 舊版演算法（次強） | 約 75% |
| 變態 `perfect` | 0 / 0 | 零誤差並以 1° / 1 力道細搜，射程內百發百中 | 約 100% |

- 命中率以三張地圖、多種風向與距離、各 288 發量測（落點進入標準彈 `damageRadius`；以「射程內可打到」為 100%）。調整誤差後須重新量測，並維持等級之間單調遞增。
- 變態等級也受射程限制：目標太遠時要先靠走位接近，所以不是每個回合都能命中。
- **打不到就改用其他砲彈**（`botBrain.ts` 的 `searchAim` / `UNREACHABLE_PX = 80`）：先照原規則抽一種砲彈（見下），暴力搜出的最佳落點離目標仍超過 80 px 就視為「這種砲彈打不到」（例如短射程的寄居蟹鉗擊彈遇到遠方目標、被地形擋住），改試其他會造成傷害的砲彈，取落點最接近目標的那一種；抽到的砲彈打得到就維持原選擇。
  搜尋本身不用亂數，所以只在需要改選時才多算幾次，亂數序列（選彈抽一次、瞄準誤差抽兩次）不變。80 px 是估計值，不在 `duel_sim.mjs` 的模型內，要實機觀察調整。測試：`battle.test.ts`「電腦 AI」（遠距離改用連發彈殼節、近距離維持鉗擊彈）。
- 電腦難度只影響瞄準，不改變坦克或砲彈數值，因此不影響 §三 的平衡驗證。

## 三之四、移動、跌落與操作（已實作）

- **移動燃料**：地圖寬約 2400 ~ 2800 px，燃料單位是 px，所以三台坦克的燃料已調高（200 / 280 / 360，見 §三表格），維持「血少者機動高」的相對關係。
  調整時要一併考慮電腦 AI 走位（`planBotMove` 以燃料範圍試算站位）。
- **走出邊緣 / 跌落**（`walkAlongTerrain(..., allowFall = true)` + `moveActiveTank`）：
  - 玩家把坦克走出橋面 / 浮空島邊緣，或走下落差超過 `FALL_SAFE_PX`（30 px）的懸崖時，坦克會往下掉：
    - 下方是**深淵**（沒有任何地面）：直接陣亡；若是出手中的坦克，立即換下一位，整場結束則進入 GAME_OVER。
    - 落在**下層地面**：依落差與機種 `fallSafePx`、`resist.fall` 結算摔落傷害（上限 30，與被炸下墜同一套規則），不會直接陣亡；摔死才換下一位。
    P2P 兩端以同一份移動指令各自算出相同結果。
  - 電腦 AI 規劃走位時 `allowFall = false`，會停在邊緣，不會自殺。
  - 緩坡、小台階不算跌落。
- **左右開火**：砲口朝向由 `angle` 決定（> 90° 朝左）。按 ←/→ 或移動鈕時車頭先轉向該側（左右鏡射仰角、不耗燃料，沒燃料也能轉向）；
  ↑/↓ 代表「抬高 / 壓低」仰角，不分左右。介面顯示仰角與朝向箭頭，儀表指針畫實際角度。轉向只在本機即時顯示，對手在開火時才看到。
- **蓄力**：每次按住空白鍵 / 發射鈕都從最小力道（10%）重新開始；放開瞬間以精確力道開火，不使用上一發的力道。
  - **到頂停住，不回退**：蓄到 100% 就停在 100%，繼續按住也不會回落，放開即以 100% 開火。
  - **Esc 取消**：蓄力中按 <kbd>Esc</kbd> 取消（視窗失焦也一樣），不開火，力道還原成蓄力前的值；之後放開按鍵也不會開火。
  - **速度固定且所有坦克一致**：`CHARGE_RATE_PER_SEC = 28`（10 → 100 約 3.2 秒；2026-10-23 由 45 調慢），不得依機種或砲彈改變。
  - **以按住時間計算力道**，不逐格累加（`useBattleInput` 的 `chargedPowerAt`）：電腦卡頓、掉幀時節奏也不變。
  - **用事件本身的時間**：按下與放開都取鍵盤 / 指標事件的 `timeStamp`（與 `performance.now()` 同一時鐘），不用處理事件當下的時間。
    主執行緒忙著畫圖時事件會晚一幀才處理，若用處理當下的時間，放開後力道還會多漲一截，感覺像放開有延遲。
  - 點擊或按住拖曳力道條可直接設定力道。
- **回合倒數與跳過回合（PASS）**：
  - 輪到真人玩家時開始倒數計時，每回合 **15 秒**（`BattleArena` 的 `TURN_TIME_SEC`；頂部記分板中央的圓章顯示秒數與倒數環，剩餘 $\le 3$ 秒時轉紅並跳動）。
  - **超時自動 PASS**：倒數歸零時不再強制以當前瞄準自動開火，改為直接執行 `ACTION_PASS` 跳過該回合，移交下一位玩家並確定性結算風向與重置燃料。
  - **主動跳過回合**：玩家可點擊發射環上方的「跳過」按鈕，或按下鍵盤快捷鍵 <kbd>P</kbd> 主動跳過本回合。
  - **P2P 同步與防偽**：跳過指令以 `ACTION_PASS { turnId, playerId }` 廣播；房主端經 `isForgedAction` 防偽檢驗，結算後比對 `SYNC_HASH` 確保雙端狀態確定性一致。
- **戰鬥介面風格**：與大廳同一套新元件庫與素材（`src/shared/ui/`、`public/assets/ui2/`，見 `docs/07`），不用 emoji 當圖示，文字不小於 12px。面板疊在全畫面畫布上，不得造成頁面捲動；中間戰場保留給拖曳鏡頭。
  - **上緣**：兩隊血條夾著回合計時環（`TimerRing`，剩餘 $\le 3$ 秒轉紅並跳動），下方「誰的回合」。換人時畫面中央彈出隊伍色的「XX 出擊！」橫幅。
  - **右上**：風向羅盤（箭頭方向 = 風向、長度與數字 = 風力）與雷達圖示鈕；點開才顯示戰場雷達小地圖，加上鏡頭移動與「對準」按鈕。
  - **左下**：燃料環與 ◀ ▶ 移動鈕。**右下**：彈種槽與跳過鈕、仰角盤與 ▲▼、發射環（按住蓄力，環上弧線即力道，黑色刻度是上一發的力道）。
  - **按住連續操作**：移動與仰角按鈕按住會連續作用，與按住方向鍵相同。
  - **駕駛艙顯示切換**：左上小卡的「我的／回合」切換鈕。
    - 「我的」（預設）：一律顯示自己的坦克；輪到別人時操作鈕停用，並顯示「等待 XX」。
    - 「回合」：跟著該回合出手的坦克。
    - 單機熱座的「自己」是最近一位出手的真人玩家。選擇存在瀏覽器的 localStorage。
